[Публічна версія EasyRecipe на ChatGPT Sites](https://easyrecipe-hol-roge.tidycypress2.chatgpt.site) · [GitHub Pages](https://artebah.github.io/ui-ux-pr3/)

## Запуск і структура

Потрібен Node.js 22.12 або новіший. Виконайте `npm ci`, потім `npm run dev` і відкрийте адресу з консолі. Для виробничої збірки виконайте `npm run build`, для локального перегляду збірки — `npm run preview`.

- `index.html` є точкою входу Vite. `src/main.jsx` містить оболонку та п’ять React-екранів. Картка рецепта, кнопка обраного, метадані та поля вибору перевикористовуються. Проп `missing` визначає статус збігу картки. Проп `detail` визначає, чи кнопка обраного показує текст.
- `src/matching.js` обчислює збіги, фільтрує каталог і сортує результати. `src/recipes.json` містить чотири демонстраційні рецепти, базові порції, інгредієнти, метадані й кроки.
- `src/style.css` містить спільні токени, стилі компонентів і мобільне компонування. Фото зі скриншотів ПЗ №2 лежать у `public/`.

## Керування станом

Поточний екран визначається маршрутом після `#`. Пряме посилання на рецепт працює на статичному хостингу з однією HTML-сторінкою. Набір обраних продуктів та параметри каталогу живуть у пам’яті поточної вкладки, тож перехід між екранами їх зберігає. Пошуковий рядок підбору, кількість порцій і позначки кроків належать поточному екрану. Результати обчислюються з даних і вибору без дублювання стану. Обране синхронізується з `localStorage` за ID рецептів та відновлюється після оновлення.

## Стек і розгортання

React оновлює інтерфейс за станом і дозволяє перевикористовувати компоненти через пропси. Vite збирає застосунок у `dist/` із базовим шляхом `/ui-ux-pr3/`. GitHub Pages віддає статичну збірку без окремого сервера або бази даних. Для більшої бази можна перенести джерело даних за API та додати посторінкову видачу. Фото рекомендацій і каталогу завантажуються ліниво, головне фото має пріоритет.

Після вибору **GitHub Actions** у **Settings → Pages → Source** workflow `.github/workflows/pages.yml` встановлює залежності, збирає застосунок та публікує його після push у `main`. Хеш-маршрути відкриваються без перенаправлень сервера.

## Адаптивність і доступність

Сітка самостійно зменшує кількість колонок, теги переносяться, а блоки головної й рецепта стають одноколонковими на вузькому екрані. Поля, посилання навігації та кнопки мають зону натискання близько 44 px або більше. Використано `header`, `nav`, `main`, посилання для переходів, кнопки для дій, підписи полів, альтернативні описи фото та видимий `:focus-visible`. Під час переходу фокус переходить до `main`. Теги й обране мають `aria-pressed`, зміни видачі озвучуються через `role="status"`. Статус збігу є текстом. Пошук без результатів і помилка завантаження мають пояснення та наступну дію.

Розраховані коефіцієнти контрасту основних пар кольорів: текст сторінки 14,42:1, другорядний текст на світло-зеленому фоні 5,75:1, білий текст основної кнопки 7,15:1, текст часткового збігу 7,51:1, текст повного збігу 9,56:1, посилання на фоні сторінки 6,68:1. Усі виміряні пари перевищують 4,5:1.

У попередній версії на ChatGPT Sites у браузері перевірено п’ять екранів при viewport 375 × 812, клавіатурний сценарій, перерахунок порцій, збереження після перезавантаження та відкриття прямого посилання на рецепт.

## Евристична оцінка сценарію

Експертний перегляд сценарію «підбір → рецепт → обране» за десятьма евристиками Нільсена. Зауваження нижче стосуються дизайну або початкової реалізації, а зміни відображені в коді.

| Евристика | Спостереження й реалізація |
| --- | --- |
| Видимість стану системи | Саме серце могло залишити дію непоміченою. Додано текстове підтвердження й лічильник результатів. |
| Відповідність реальному світу | Кількість збігів мало допомагає на кухні. Групи пояснюють, що можна готувати зараз, а в часткових збігах названо відсутні продукти. |
| Контроль і свобода | Помилковий вибір виправляється повторним натисканням на тег або очищенням. Збереження можна скасувати на картці чи в «Обраному». |
| Послідовність і стандарти | Єдина картка й та сама кнопка обраного на головній, у підборі, каталозі та списку збережень. |
| Запобігання помилкам | Запит про продукт фільтрує наявні теги. Довільний текст не стає помилковим інгредієнтом. |
| Упізнавання замість запам’ятовування | Обрані теги залишаються видимими під час пошуку. На картці показано потрібні продукти. |
| Гнучкість і ефективність | Теги дають швидкий вибір, пошук прискорює доступ, а фільтри каталогу зберігаються при поверненні з рецепта. |
| Естетичність і мінімалізм | Повні збіги відокремлено від варіантів, що потребують покупок. Довгі інструкції винесено на сторінку рецепта. |
| Розпізнавання та виправлення помилок | Для порожньої видачі є дії «додати інші інгредієнти» або перейти до каталогу. При помилці завантаження є «Повторити». |
| Допомога та документація | Короткі підказки вбудовані у вибір продуктів і порожнє «Обране». |

## Сценарій захисту

Відкрийте «Підбір». Оберіть яйця та молоко, покажіть, чого бракує для омлету. Додайте сир і покажіть, як омлет переходить у групу повних збігів. Відкрийте рецепт, змініть кількість порцій, позначте крок, збережіть страву. Перейдіть в «Обране», оновіть сторінку й покажіть, що рецепт збережено. Продемонструйте видимий фокус і вибір тегу клавішею пробілу та коротко поясніть локальний стан, спільну картку і статичний деплой.
